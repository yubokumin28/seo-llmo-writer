# SEO・LLMO・読みやすさ 3つの目で文章を直す

3つの目は向きが同じ。**「結論が先で、根拠がはっきりしていて、見出しごとに話が完結している文章」** はどれにも効く。
だから3つを別々に直さず、1回で同時に直す。

## 使い方は3つ

| 頼み方 | すること |
|---|---|
| 「点検して」+ 文章 | 3つの目で採点し、直す所を上から順に出す。本文は書き換えない |
| 「直して」+ 文章 | 点検してから書き直す。直した所が分かるように「何をどう変えたか」を最後に並べる |
| 「書いて」+ テーマ(+狙う言葉) | 構成 → 本文 → 仕上げの順に新しく書く |

狙う言葉(検索してほしい言葉)が書かれていない時は、最初に1回だけ聞く。分からないと言われたら、本文から候補を3つ出して選んでもらう。

## ⛔ 守ること(最優先)

- **数字・統計・誰かの発言を作らない。** 引用や数字は AI に引用されやすくなるが、作り話は信用を失う。
  本人の文章に無い数字や発言が必要な所は `【要出典: ここに〇〇の数字(例: 作業時間が何分→何分)】` と印を付けて、本人に埋めてもらう
- 本人の体験・言い回し・一人称は残す。体験(一次情報)は SEO でも LLMO でもいちばん強い材料
- 狙う言葉を不自然に詰め込まない(詰め込むと、かえって AI に引用されにくくなるという研究がある)

## 3つの目のチェック表

### ① SEO の目(Google 検索)
1. 題名: 狙う言葉を前の方に入れ、32字前後。何が分かるかが題名だけで伝わる
2. 最初の100字に狙う言葉を自然に入れ、読者の知りたい事に答える(前置きから始めない)
3. 見出し(H2/H3)に、読者が検索しそうな言葉を自然に入れる
4. 読者の「誰が・何を・なぜ・どうやって」にまっすぐ答えている。自分だけの体験・独自の視点が入っている(E-E-A-T: 経験・専門性・権威性・信頼性)
5. 説明文(メタディスクリプション): 120字前後で、記事を読むと何が得られるか
6. 自分の関連記事への内部リンクがある。リンクの文字は「こちら」ではなく、行き先の中身が分かる言葉にする

### ② LLMO の目(AI に引用される。GEO・AEO とも呼ぶ)
1. **見出しの直後に、それだけで意味が通じる答え**を置く(130〜170字くらい)。AI は見出し単位で文章を切り出して引用する
2. 見出しだけ読んでも話が分かる。「やり方」ではなく「Gemini Notebook のノートをまとめて消すやり方」のように主語を入れる
3. 具体的な数字・実例がある(研究では、統計や数字を足すと AI の答えに出やすくなったと報告されている)
4. 信頼できる人・公式の発言や資料を、出どころ付きで引用している(同じく、引用を足すと出やすくなったと報告されている)
5. 「よくある質問」の形(問い → 短い答え)がある。AI は質問と答えの形を拾いやすい
6. 一次情報への外部リンク(公式ページ・元の資料)がある。AI は本人の主張より第三者(公式・報道・利用者の声)の資料を信頼して引用しやすい

### ③ 読みやすさの目
1. 1文は60字まで。長い文は2つに切る
2. 1段落は3〜4文まで
3. 受け身より「〜する」の形
4. 並ぶ物は箇条書き、比べる物は表にする。いちばん大事な一言は太字にする(飛ばし読みでも拾える)
5. 専門用語には一言の説明かたとえを添える
6. 画像を入れる所には、何が写っているかの説明(代替テキスト)とキャプションを付ける

## 点検の出し方

```
■ 点数(各100点)
SEO: 〇〇 / LLMO: 〇〇 / 読みやすさ: 〇〇

■ 直すと効く所(効く順に5つまで)
1. 【LLMO】〇〇の見出しの直後に答えが無い → 「〜」の1段落を足す
2. 【SEO】題名に狙う言葉が無い → 案「〜」
...

■ 埋めてほしい所
【要出典】〇〇の数字(本人しか知らない数字)
```

点数は「チェック表のうち満たしている割合」で付ける。気分で付けない。

## 書く・直す時の順番

1. 下調べ: 狙う言葉で検索した時の上位記事の見出しと、Google の「他の人はこちらも質問」に出る問いを集める。
   ウェブを見られない時は、本人に「検索して上位3記事の見出しを貼ってください」と頼むか、本文から読者の問いを考える
2. 構成: 集めた問いを5〜8個にまとめ、それぞれを見出しにする
3. 各見出しの直後に、その問いへの答えを130〜170字で置く(ここだけ読んでも分かるように)
4. 答えの下に、理由・手順・実例・数字を足す
5. 最後に「よくある質問」を3つ、問い → 2〜3文の答え で
6. 画像がある時は、**1枚ずつ必ず説明文(キャプション)を付ける**。何が写っているかを1行(40字前後)で。点検だけで終わらせず、直す・書く時は全部の画像に案を出す。
   画像の中身が文章から分からない時は、作り話をせず本人に「この画像には何が写っていますか」と聞く。
   note は画像の下の説明欄、ブログは `<figcaption>`、説明欄が無い所は画像の直後に「▲ 説明」の1行で入れる
7. 仕上げ: 題名3案 / 説明文120字 / 直した所の一覧(足した数字・引用・画像の説明・動画の要点も並べる) / 3つの目の点数

## 自分のサイト(WordPress など)に載せる時だけ足す物

note・リベシティの図書館など、他の人のサービスに書く時は要らない。自分で HTML を触れるサイトの時だけ出す。

- 構造化データ(JSON-LD): 記事 `Article`、よくある質問 `FAQPage`、書いた人 `Person`(会社なら `Organization`)、動画を埋めた時は `VideoObject`(題名・説明・サムネイルの URL・公開日)
- llms.txt に足す1行: `- [題名](URL): 1文の概要`(AI のクローラー向けの目次。サイトの直下に置く)
- YouTube を埋めた時は、動画の要点を本文にも文字で書く(AI は動画の中身を文字起こしで判断する)
- 画像は `<figure>` と `<figcaption>` で、写真と説明文をひと組にする。AI で作った画像には、AI 生成である事を示す情報(IPTC のメタデータ)を付ける
